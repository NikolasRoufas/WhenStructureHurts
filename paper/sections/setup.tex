\section{Experimental Setup}
\label{sec:setup}

\paragraph{Questions.}
The pilot sample (seed~1), fixed before any generation, contains 100 MuSiQue questions stratified by hop count, 100 2WikiMultiHopQA questions stratified by question type and, as secondary datasets, 50 questions each from HotpotQA, HoVer and FEVER; questions without gold evidence or (for QA) a reasoning order are ineligible, and the fifteen questions used during prompt development are excluded. We first run the 200 MuSiQue and 2WikiMultiHopQA questions (the \emph{focused pilot}) and then the complete 350-question set (the \emph{expanded pilot}); generations shared between the two are served from a cache keyed on the full prompt and every decoding setting, so they are identical by construction. After the pilot we wrote and committed a confirmatory protocol, and only then drew a \emph{confirmatory sample} with a different seed (2) from the questions that the pilot and prompt development had not used: 1{,}744 MuSiQue questions (hop 2/3/4: 687/686/371, the last stratum exhausting the eligible pool) and 3{,}232 2WikiMultiHopQA questions (808 per type). Its size is the number of questions needed for 80\% power to detect a difference of 0.03 exact match at $\alpha=0.05/6$, computed from the pilot standard deviation of paired differences inflated by 20\%, maximised over the three contrasts of each dataset. The confirmatory run uses Protocol~A only.

\paragraph{Answerer.}
The answerer is Qwen2.5-7B-Instruct \citep{qwen2024qwen25} at the pinned revision \texttt{a09a3545}, in bfloat16, with greedy decoding, at most 64 new tokens and at most 4{,}096 input tokens. Auxiliary models are bge-small-en-v1.5 (dense retrieval in B4), ms-marco-MiniLM-L6-v2 (reranking), nli-deberta-v3-xsmall (relation prediction) and nli-deberta-v3-small (grounding), all pinned \citep{he2023debertav3}. Experiment~0 also uses the 7B model as its claim extractor.

\paragraph{Hardware and batch size.}
All generations run on a single NVIDIA RTX~5000 Ada GPU (32\,GB; CUDA~13.0, PyTorch~2.12.1, Transformers~5.12.1) with batch size~1. In a preflight on questions excluded from all reported runs, batched bfloat16 greedy decoding changed 3 of 8 outputs of the 7B model, including one answer, whereas unbatched outputs were identical across runs. Batching would thus have made outputs depend on which prompts share a batch, and batch composition depends on prompt length and hence on the representation.

\paragraph{Statistics.}
The unit of analysis is the question. For each contrast we report the paired difference in question-level EM over the questions available in both conditions, with a 95\% percentile bootstrap interval (2{,}000 resamples, seed~0) and a two-sided bootstrap $p$-value \citep{efron1993bootstrap}; R2 seeds are averaged within a question before pairing. Every contrast also reports the number of questions whose two evidence blocks are byte-identical (for example, R5 equals R1 when the graph-derived order coincides with the dataset order), the same estimate restricted to the remaining \emph{informative} pairs, and the paired difference in coverage. Protocols, datasets, budgets, policies and edge strata are never pooled. As secondary analyses we report the exact McNemar test on discordant pairs \citep{mcnemar1947} and the standardised paired effect $d_z$. All these procedures, the primary metric and the primary contrasts were fixed in a pilot protocol before any generation. The confirmatory family consists of the six primary tests (three contrasts on two datasets) on the confirmatory sample, with Holm correction \citep{holm1979} at a family-wise $\alpha$ of 0.05; we also report whether the 90\% interval lies inside a pre-specified equivalence margin of $\pm0.02$. Everything else, including all pilot results, the secondary contrasts on the confirmatory sample, and the analyses that we added after seeing the confirmatory result, is exploratory and reported as such. An interval that contains zero is reported as inconclusive, never as evidence of equivalence.
